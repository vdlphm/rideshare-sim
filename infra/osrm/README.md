# OSRM

Routing backend (OSRM v5.27.1, MLD algorithm) over a downtown Seattle clip.

- `seattle.osm.pbf`: committed map data (generated by `clip.sh`).
- `compose.yml`: `osrm-prep` (one-shot) and `osrm` (router, port 5000, internal only, not published to the host). Routing service URL: `http://osrm:5000`.
- `prep.sh`: run by `osrm-prep`.

## How prep works

`osrm-prep` hashes the pbf (sha256) and compares it with `/data/.source.sha256` in the `osrm-data` volume. On a match it logs "up to date" and exits immediately. Otherwise it runs `osrm-extract` -> `osrm-partition` -> `osrm-customize` in a temp dir inside the volume (about 2 s), moves the results into place, and writes the checksum file last, so a crash never leaves a half-built graph marked as done. `osrm` starts only after prep completes successfully.

## Force a rebuild

- Wipe everything: `docker compose down -v` (removes the `osrm-data` volume).
- Or delete only the checksum: `docker compose run --rm --entrypoint rm osrm-prep -f /data/.source.sha256`, then `up` again.

## Refresh the map

Run `infra/osrm/clip.sh` to regenerate `seattle.osm.pbf` and commit it. The checksum changes, so the next `up` rebuilds the graph automatically.
